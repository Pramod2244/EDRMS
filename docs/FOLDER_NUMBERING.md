# Folder tree and document numbering

Repository Files shows the Folder Tree on the left. Show Folders restores it when hidden. Top-level folders initially expand; arrow controls expand/collapse children without changing folder access. Find a folder includes its ancestors as context.

Repository Files > Folder numbering opens a configuration screen for existing folders. New folders receive default settings automatically. Existing folders receive settings through additive migration V6. Defaults use a unique DOC/UUID prefix, no date, four minimum sequence digits and next number 1001. A manager can replace the prefix with MEDDOCS or ADMDOCS and choose no date, year, year/month, or year/month/day. Dates use Asia/Kolkata. No arbitrary formulas or separators are accepted.

Examples: MEDDOCS-1001, ADMDOCS-2026-10-07-1001. A sequence is mandatory because a date alone repeats within the day. Next number may only move forward. Sequence does not reset on calendar changes. Prefix reservations stay associated with their original folder even after configuration changes. Changing formats never renumbers existing documents. Pre-existing documents retain their original metadata and have no new reference ID; no backfill is performed.

IDs are allocated inside the document-save transaction under a PostgreSQL row lock. Counter updates and document creation commit together, and an immutable document reference column has a unique index. Failed transactions may reuse uncommitted numbers; committed document IDs cannot be reassigned through the application. Deletion is soft and keeps the reference. Configuration revisions prevent stale edits from overwriting concurrent upload increments. Uniqueness depends on retaining the database and reservation history; restoring an old database or manually removing history requires operational controls.

The upload dialog shows an example next ID without reserving it. Another upload may consume that number before save. The repository displays the actual reference alongside the original filename and supports filtering by reference. Phone captures receive an example via their existing capture link and the actual ID in the completion response. PDF creation and original filenames remain unchanged.

Configuration writes require SUPER_ADMIN or MANAGE_PERMISSIONS; reads require an active authenticated user and exact folder access where restricted. These additions do not fix the pre-existing general authorization findings documented in PROJECT_REVIEW_2026-10-07.md.
