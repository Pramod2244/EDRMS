# EDRMS changes — 7 October 2026

Based on `main_changes` (`a455ba1`). This document summarizes the changes delivered during the project review.

## Repository and search experience

- Search uses the available screen width with a scrollable results area and fewer unnecessary requests.
- Search requests use cancellation/debouncing to avoid stale results.
- PDF previews render pages near the visible area and use a lighter scroll listener.
- Backend search batches document lookups and backs off when OpenSearch is unavailable.
- Folder Tree shows top-level folders expanded, supports folder filtering and named expand/collapse controls, and renders expanded children only.
- Restricted users see parent folders as navigation context; selecting a folder for access does not automatically select descendants.

## Roles and user administration

- Added a role catalog with protected built-in roles and configurable custom role templates.
- Custom roles define menu and action permission defaults for new assignments.
- Existing user permissions remain in place; choosing a template does not retroactively overwrite other users.
- User setup uses a wider responsive form with visible save/cancel actions.
- New role-management endpoints require active authentication and permission-management access.

## NAS storage and OCR

- Added NAS root configuration through `STORAGE_NAS_ROOT_PATH` and connection/path checks.
- Missing or unreachable NAS storage fails explicitly rather than silently switching to local storage.
- Original document and thumbnail access use the document's recorded storage provider.
- Removed the OCR 25-page cutoff; scanned PDFs can process all pages.
- Native OCR execution checks exit status, applies a timeout, validates output and cleans temporary files.
- Corrected pipeline page-count handling.
- Real NAS hardware, service-account/share permissions and outage recovery still need environment-specific testing.

## Phone scanning

- Added expiring, upload-only QR capture links tied to an existing destination folder and account.
- The phone route fills the viewport with compact Arkaa Digital / EDRMS branding.
- Camera/gallery choices use native phone pickers. Camera photos open a confirmation preview with Use this page, Use & next photo and Retake.
- Gallery imports appear incrementally; a later unreadable photo keeps already added pages.
- Review supports rotation, border trim, page order changes and removal.
- Supported browsers prepare images in a disposable background worker; other browsers retain a native image/canvas fallback.
- Preparation/check/upload deadlines, cancellation, preview URL cleanup and retry handling reduce stuck states.
- Stop ends active client operations; it cannot undo a server save that already completed. Completed capture retries do not create another document.
- Images assemble into a PDF on the backend. The screen reports photo payload MB, upload progress and final PDF size.
- Backend validation checks format, size, image quality and actual Tesseract OCR confidence before confirmation and again before final upload.
- Corrected an overly strict resolution rule that rejected a readable 803 × 916 image before running OCR. Images above thumbnail size now proceed to readability checks.
- Native Android/iOS camera behavior, lower-memory devices, real scan quality and poor-network acceptance remain outstanding.

## Folder document numbering

- Added Repository Files → Folder numbering, with folder selection and a live example ID.
- Existing and new folders receive default settings: unique DOC/UUID prefix, no date, four minimum sequence digits and next number 1001.
- Configuration permits a controlled prefix, optional year/month/day, minimum sequence digits and a forward-only next number.
- Example formats: `MEDDOCS-1001` and `ADMDOCS-2026-10-07-1001`. Sequence is mandatory because a date alone is not unique.
- Dates use Asia/Kolkata; sequence never resets on a calendar change.
- Prefix reservations belong to one folder and remain reserved after configuration changes.
- IDs are assigned during the document-save transaction under a PostgreSQL row lock and protected by a unique database index.
- Configuration revisions prevent stale edits from overwriting concurrent increments.
- Existing filenames and document IDs are not renamed or backfilled. Newly issued IDs are immutable.
- Upload shows an example; the actual saved ID appears beside the original filename and can be used in the repository filter.
- Phone capture shows a next-ID example and receives the actual ID after save.
- Med Docs was configured as MEDDOCS. A synthetic verification PDF received MEDDOCS-1001; the next number is 1002.

## Recycle Bin and application configuration

- Added a separate Recycle Bin menu for administrators and users with delete permission and repository access. Backend routes enforce active authentication and exact folder restrictions.
- Document deletion now records its deletion time, actor and recovery deadline. Files, pages and versions remain available during the recovery window.
- Default retention is 30 days. System Admin → Application Configuration exposes a validated whole-number field (1–3650 days).
- Configuration uses a controlled typed settings catalog with number/boolean support. Future flags require an implemented definition and behavior; upload-block and special-allowance flags are not enabled by this change.
- Retention changes apply to future deletions; existing deadlines remain unchanged. Previously hidden documents receive a fresh 30-day window when migration V7 is applied.
- Recycle Bin lists the original folder, document ID, deletion date and recovery deadline, with search, pagination and Restore.
- Restore preserves the ID, filename and folder. Expired documents, missing originals and unavailable original folders cannot be restored.
- Expired cleanup runs in bounded background batches while the backend is running. Storage failures retry, and ongoing ingestion is skipped. Files, page content, assets and versions are removed; a document tombstone/reference and audit history remain so IDs are never reused.
- Locked recycle updates prevent a concurrent pipeline save from reversing deletion. Search updates run after commit in the background.
- Fixed the old frontend delete flow that hid documents even when the backend rejected deletion. Errors now keep the document visible.
- Browser verification moved the synthetic numbering-test.pdf to the bin with a 30-day deadline and restored it with MEDDOCS-1001 unchanged. Admin configuration loaded and saved 30 successfully.
- This update passed the production frontend build and 46 backend tests; the opt-in PostgreSQL numbering test was skipped in this run (it passed during the previous numbering verification).

## Database migrations

- `V5__role_templates_and_mobile_capture.sql`: role template metadata and mobile capture links.
- `V6__folder_document_numbering.sql`: folder settings, historical prefix reservations and unique document reference IDs.
- `V7__recycle_bin_and_application_settings.sql`: recovery timestamps, cleanup metadata, expiry index and default retention setting.
- Apply migrations through the normal backend startup process. Retain database history/backups to preserve issued IDs; restoring an older database requires operational controls.
